# 6.9.0 to 6.x.x

## Jingle push notification content

The `jingle` content source in [`mod_event_pusher_push`](../modules/mod_event_pusher_push.md) rules no
longer generates a regular notification containing `message-count`, `last-message-sender` and a
synthetic `last-message-body`. It now generates a Jingle Message Initiation (JMI) payload containing:

* `type` set to `jmi`,
* `jmi-sid` set to the Jingle session ID,
* `jmi-from` set to the sender's full JID.

With `mod_push_service_mongoosepush`, JMI notifications are always sent as data-only notifications.
For APNS, they are sent only to registrations whose topic ends in `.voip`, which require a PushKit
device token. Ensure that MongoosePush supports JMI notifications and update custom push integrations
that expect the previous notification fields. See the
[client-side push notification tutorial](../tutorials/push-notifications/Push-notifications-client-side.md#publish-options)
for the registration options.
